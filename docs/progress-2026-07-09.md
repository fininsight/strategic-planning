# 진행상황 및 할일 정리 (2026-07-09)

## 정리 기준

이 문서는 이전 진행상황 정리 이후 현재 브랜치(`feature/proposal-strategy`)에서 추가로 진행된 내용을 정리한 것이다. 기준은 마지막 커밋 `e2f5322 fix: 로컬 Docker 테스트 환경과 API 경로 처리 정리` 이후의 로컬 변경사항이다.

## 진행상황

### 1. 제안 분석 시트 고도화

- 제안 분석 화면을 기존 3개 탭에서 `공고정보`, `요구사항`, `제출서류`, `배점표` 4개 탭 구조로 확장했다.
- 공고정보를 단순 상세 목록이 아니라 `사업 개요`, `평가 방식`, `제출 형식 제한`, `일정·방법`, `공동수급 의무` 그룹으로 나누어 표시하도록 개선했다.
- 요구사항 전용 탭을 추가해 ECR/SFR/PER/PPR/IFR/DAR/TER/SER/QUR/COR/PMR/PSR 등 원문 요구사항 코드와 요구사항명을 분리 표시한다.
- 요구사항 코드별 색상 구분, 요구사항 개수 요약, 분류/유형/세부내용 표를 추가했다.
- 독소조항·특이 요건과 발주처 질의 필요 지점을 공고정보 탭에서 별도 영역으로 볼 수 있게 했다.
- 배점표 화면은 기술능력평가/가격평가 등 상위 평가 구분과 세부 평가항목을 더 잘 드러내도록 요약 스트립과 색상 그룹을 보강했다.

### 2. 분석 로직 개선

- `proposal_sheet_analyzer.py`에서 요구사항 총괄표, 요구사항 목록, 요구사항 상세, 배점표, 제출서류 섹션을 우선 추출하도록 LLM 입력 구성을 크게 개선했다.
- LLM 프롬프트에 원문 요구사항 코드와 요구사항명을 임의 정규화하지 말라는 규칙을 추가했다.
- 요구사항, 제출서류, 배점표에 대해 룰 기반 사전 추출 결과를 LLM 입력에 함께 제공해 누락 가능성을 줄였다.
- 제출서류 후보 목록을 확장했다. 신용평가, 재무제표, 실적증명, 투입인력, 자격증, SW사업자 신고확인서, 직접생산확인증명서, 중소기업확인서, 하도급 관련 서류 등이 추가됐다.
- 조건부 서류(`대면평가 시`, `요청 시`, `계약 체결 후` 등)는 실제 제출 체크리스트에 과도하게 포함되지 않도록 필터링을 추가했다.
- 배점표 파싱은 압축형 표, 일반형 표, 상세형 표를 순차적으로 해석하도록 확장했다.
- HWPX 텍스트 추출은 본문 XML과 미리보기 텍스트를 비교해 더 긴 본문을 우선 사용하고, 필요한 경우 둘을 병합하도록 개선했다.
- 분석 버전을 `30`으로 올려 기존 캐시보다 새 분석 로직이 우선 적용되도록 했다.

### 3. 제출서류 구비 체크 저장

- 제출서류 탭에 `구비유무` 체크박스를 추가했다.
- 체크 상태는 우선 브라우저 `localStorage`에 저장하고, API 서버가 연결되어 있으면 백엔드에도 저장한다.
- 백엔드에 `/api/notices/{bidNo}/{bidOrd}/checklist-state` GET/PUT/POST API를 추가했다.
- DB 사용 시 `proposal_checklist_states` 테이블에 저장하고, DB가 없거나 실패하면 `.local-data/checklist-states/`의 JSON 파일로 폴백한다.

### 4. 시장·경쟁 리서치와 회사자료 RAG 연동

- `backend/app/services/knowledge/company_knowledge.py`를 새로 추가해 로컬 회사자료 RAG 1차 버전을 구현했다.
- 회사소개서, 수행실적, 인력/조직, 솔루션 자료를 `.local-data/company-knowledge/sources/`에 두면 텍스트 추출, 청킹, 토큰 기반 유사도 검색, `index.json` 캐시 생성을 수행한다.
- 시장·경쟁 리서치 생성 시 회사자료 검색 결과를 `companyEvidence`로 함께 반환하도록 연동했다.
- 회사자료는 핀인사이트 강점과 내부 증빙 근거로 사용하고, 시장 규모·성장률·수주사실·법령·고시번호 같은 외부 사실은 웹 출처가 있을 때만 검증된 항목으로 다루도록 프롬프트를 강화했다.
- 웹검색 결과가 짧거나 일부 섹션이 빈 경우 경쟁 후보, 트렌드, SWOT, 경쟁우위, 팩트체크 초안을 보강하는 fallback 로직을 추가했다.
- 전략수립 화면에 `재조사` 버튼을 추가해 시장·경쟁 리서치를 강제로 새로 생성할 수 있게 했다.
- 전략수립 화면에 `핀인사이트 내부 근거` 섹션을 추가해 회사자료 RAG 검색 결과를 직접 확인할 수 있게 했다.
- 회사자료 RAG 도입 전 생성된 시장조사 캐시는 `companyEvidence` 스키마가 없으면 재생성되도록 캐시 판별 조건을 보강했다.

### 5. 설정 및 실행환경 정리

- `COMPANY_KNOWLEDGE_DIR` 환경변수를 추가했다. 기본 경로는 `.local-data/company-knowledge`다.
- Docker Compose 설정에 회사자료 디렉터리 관련 환경 구성을 추가했다.
- `python-dotenv`가 없는 최소 로컬 런타임에서도 서버가 바로 죽지 않도록 optional import 처리했다.
- `docs/company-knowledge-rag.md`에 회사자료 RAG 운영 메모를 추가했다.

## 현재 상태

- 주요 기능 구현은 대부분 로컬 변경사항으로 반영되어 있다.
- 아직 커밋되지 않은 변경 파일이 다수 있다.
- 새로 추가된 회사자료 RAG 문서와 `backend/app/services/knowledge/` 디렉터리는 아직 git 추적 대상에 올라가기 전 상태다.
- 기능 검증은 별도로 실행 기록이 확인되지 않았다. 특히 분석 API, 프론트엔드 화면, DB/파일 폴백 저장 동작은 한 번에 통합 확인이 필요하다.

## 남은 할일

### 우선순위 높음

- 분석 API 서버를 실행해 `/proposal-analysis`, `/checklist-state`, `/proposal-mapping`, `/strategy-market-research` 흐름을 실제 공고 기준으로 확인한다.
- 프론트엔드에서 분석 탭 4종이 정상 렌더링되는지 확인한다.
- 제출서류 체크박스가 새로고침 후에도 유지되는지 확인한다.
- DB 연결이 있는 환경과 없는 환경에서 체크 상태 저장 폴백이 각각 정상 동작하는지 확인한다.
- 시장·경쟁 리서치 재조사 버튼이 캐시를 우회해 새 결과를 받아오는지 확인한다.
- 회사자료가 없는 상태, 일부만 있는 상태, 여러 문서가 있는 상태에서 RAG 경고와 검색 결과가 자연스럽게 표시되는지 확인한다.

### 우선순위 중간

- 실제 HWPX/RFP 샘플 2~3개로 요구사항 코드 추출 정확도를 비교한다.
- 배점표가 압축형/일반형/상세형으로 다른 공고에서 모두 안정적으로 추출되는지 샘플 검증한다.
- 제출서류 체크리스트가 중복·조건부 서류를 과도하게 포함하지 않는지 실제 공고별로 튜닝한다.
- 회사자료 RAG의 단순 토큰 유사도 검색이 부족한 경우 BM25 또는 임베딩 기반 검색으로 확장할지 결정한다.
- `pptx`, `docx`, `xlsx` 회사자료를 직접 지원할지, PDF 변환 업로드 원칙을 유지할지 정한다.

### 우선순위 낮음

- RAG index 재생성 버튼 또는 관리용 API를 추가할지 검토한다.
- 회사자료 근거별 원문 위치, 페이지 번호, 파일 열기 링크를 제공할 수 있는지 검토한다.
- 팩트체크 결과에서 `AI 전략 초안`, `회사자료 근거`, `웹 출처 검증` 라벨을 더 명확히 분리한다.
- 분석 결과 JSON 스키마 변경 내용을 README 또는 별도 API 문서에 반영한다.
